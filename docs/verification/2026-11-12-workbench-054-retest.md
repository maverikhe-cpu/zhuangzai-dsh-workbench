# 装仔工作台 0.5.4 场景复测

日期：2026-11-12。DSH 桌面版，GLM-5.3 / Default，真实已授权公司数据。本文不包含客户明细或凭据。

## 方法

从工作台点击入口，新建装仔会话并发送，通过桌面轨迹核对技能、方法文件、业务接口和结果。8类管理场景各首题及2个推荐入口均实测；全部22个问题另做前端传参回归。候选包按发现的问题逐次修正，最后修改涉及的月报另行复测。未受影响场景保留此前结果，不宣称每次修改后都重跑所有模型任务。

时间为界面端到端时间，测试任务存在并行，不是串行网络基准。此前0.5.3使用不同模型，不计算跨版本速度提升百分比。

## 场景结果

| 入口 | 路径 | 耗时 | 结果 |
|---|---|---|---|
| 今天先关注哪里 | priorities；问题、逾期工地、3个详情 | 2分33秒 | 5次业务调用；3个主要重点与真实看板链接；实际阶段来自工地字段；无派工/设备查询 |
| 管工地：我负责 | 确认身份后组织树、工地、阶段、问题 | 含人工确认，不计性能 | 确认前0次业务调用，指定部门后4次；全公司权限不当个人负责范围 |
| 管人员：本周派工缺口 | dispatch；缺口汇总 | 2分14秒 | 1次业务调用，首次即限定本周计划进场日，不先查全历史 |
| 管问题：近7天跟进 | issues；三类状态各1次列表 | 首轮2分42秒，补查55秒 | 首轮待处理超时即停；用户要求恢复后只补查失败状态；区分总数与20条样本、待审核与闭环 |
| 管工期：阶段落后 | progress；逾期在建列表、批量阶段 | 2分30秒 | 2次业务调用，限定首批候选，未启动多助手扫描 |
| 管质量：报告与待验 | acceptance；报告、3个工地待验节点 | 3分13秒 | 4次业务调用；未配置计划不等于无漏验；提交不等于业主确认；排名仅覆盖已返回报告 |
| 管现场：问题与画面 | issues、visibility；问题列表、重点详情 | 2分43秒 | 2次业务调用；3个工地、前2个配图、第3个提供入口 |
| 管设备：绑定中离线 | 台账简单查询 | 59秒 | 1次台账查询，筛选绑定且离线；总数和5台，不扩展历史在线率 |
| 管客户：业主关注 | owner；观看2页、3个问题查询 | 3分28秒 | 5次业务调用，限定100条样本，不冒充公司全部观看排名 |
| 生成管理汇报 | report；负荷、派工、设备汇总，当月问题与验收 | 3分11秒；6次业务调用 | 当前快照与当月事件、非冲突完工桶与冲突桶分别标注；报告数量不证明无漏验 |

上述场景没有自动启动子助手。模型建议存在表述差异，例如主要清单后偶尔补充一个候选；回归重点为正确取数、关键口径与范围，以及没有无界扫描和错误重试。

## 故障与性能

- 真实网络超时覆盖问题和月报。代理至多额外重试1次，返回耗尽信号；模型没有换业务工具探测网络、搜索本地配置或连续重试，成功模块保留。
- 问题恢复只补查失败状态；月报旧候选的续问只补齐问题/验收，没有重取已成功派工、负荷、设备。
- 普通首轮最多6次业务调用，简报最多10次；小列表与分析分流，汇总优先，明细/图片只取重点。
- 月报当月问题返回量仍可能较大；本轮验证管理简报，不代表固定格式HTML/Excel月报交付验收。
