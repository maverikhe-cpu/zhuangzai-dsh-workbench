# 大任务取数与性能

## 最短路径

- 列几条及指定字段先走 SKILL.md 的简单查询路径，不为公司名或附加背景调用无关业务工具。先判断需要计数、分布、排名还是个案。使用当前可用且同口径的汇总；少数计数可读准确 total；分组、去重或加权才取完整明细。不要加载无关技能资料和工具定义。
- 首个成功页直接保留，不丢弃重查。固定筛选、排序与页大小，记录成功页、失败位置和返回范围。改页大小需重算边界；总数变化、重复 ID 或排序漂移先解决一致性，不无限重拉。
- 工具返回本次结果文件时直接读该文件。否则仅在宿主支持时保存本次完整 JSON 并程序聚合；不手抄数百条，不扫描其他任务日志/缓存/凭据。截断或缺页不称完整。
- 完整明细一次分组、去重与校验，只有发现差异或用户要求对账才再查。施工动态 total 是下界，取到短页；无独立 ID 的事件不能按姓名/日期随意去重。

## 控制展开范围

| 场景 | 优先路径 | 展开限制 |
|---|---|---|
| 负荷 | 汇总的完整分组；有公司规则时传 finalStages | 明细分页不影响全分组；岗位/零负荷才查底册，不逐经理重取全公司 |
| 派工 | 缺口汇总按 include 选段 | Top N 只是裁剪输出；超时不能靠缩小 applications 页大小解决后端全量成本 |
| 设备 | 公司快照计数；交叉分布取台账 | period 算期间在线率；只有日趋势用 day；不逐台查历史 |
| 进度 | 阶段比较按实时 projectIds 上限批量（本次为100） | 节点、AI、图文、照片只展开重点工地 |
| 验收 | 报告列表完整分页后分组 | 审核/检查项只查重点；漏验需节点数据，不由报告反推 |
| 问题、巡检、签到、AI、观看 | 按模块、正确日期与权限批量取 | ID 关联；不逐工地重复取全公司数据 |

普通首轮最多6次业务调用，月报简报最多10次；预算包含探查、重试和下钻，达到后交付已取结果。用户明确要求全量才继续完整分页。默认最多深入 5 个重点对象作第一轮说明；这是个案分析的取数预算，不是全量统计的抽样替代。用户明确需要完整明细且预算足够时继续已记录的分页计划。

## 停止条件

错误分类、重试上限统一执行 [工具与回退](tool-fallbacks.md)，不在各模块另设重试循环。多页全量若需要拆时段，使用互不重叠区间、保留边界与完整覆盖；不要将多个 Top N 拼成全局 Top N，不平均分段百分比。汇总分段无法可靠合并时改取明细或交付各期结果。

遵循用户时间预算。未指定时，日常分析 2 分钟做一次进展判断，大任务 5 分钟检查已覆盖范围、剩余量与是否仍有有效进展；这些是检查点，不是完成时限承诺。超出预算不盲目继续新路径，交付已有结果并说明剩余工作。宿主不可取消在途请求时不重复并发发同一请求。

## 性能测试记录

测试时记录准备、首次有效数据、全部取数、计算和最终交付各阶段及成功/失败调用数；接口耗时不能冒充端到端耗时。最终生成前只能报告“截至当前”；宿主可见的完成时长才是端到端证据。日常业务回答不用输出整套诊断日志。
