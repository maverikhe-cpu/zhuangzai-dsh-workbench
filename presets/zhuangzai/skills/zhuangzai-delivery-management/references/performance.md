# 大任务取数与性能

## 选择最短数据路径

- 只查看本次所需工具的实时 schema；工具清单已在上下文时复用。先判断目标是计数、分布、排名还是个案，再选择数据粒度。
- 有已上线且同口径的汇总优先用汇总；没有就按当前工具能力执行，不调用提案中的工具名。计数用筛选 total；需完整分组、排名时才取全，分页按各工具上限选择合理大小。大页超时不证明小页总任务更快。
- 首个成功页同时用作总量估算和数据输入，不丢弃后再重取同页。固定筛选、页大小和排序，记录成功页及失败页；断点继续只补缺页。若切换页大小，重新规划分页，不能混接不同页边界；total 变化、重复ID或不稳定排序需先解决一致性再报告完整结果。
- 按工具实际分页语义结束：准确 total 的列表核对页数、行数、唯一ID；施工动态 total 为下界，仍按短页结束。没有独立ID的记录按工具定义保留粒度，不能擅自去重删除事件。
- 原始数据量大时，使用宿主明确返回的**本次工具结果文件引用**，或将本次完整响应保存后程序计算。不要由模型手抄数百条JSON。文件必须对应同一授权公司、查询范围和本次调用；不扫描历史日志、凭据、其他任务或旧缓存。文件不存在或响应截断不能称取全。
- 完整数据一次计算总数、唯一键、未知/缺失值、分组和。已知完整明细无需另发每个状态、每个部门的计数请求；存在差异再针对性核对。用户明确要求独立对账时保留对账步骤与单独耗时。

## 各场景避免请求膨胀

| 场景 | 优先路径 | 何时下钻 |
|---|---|---|
| 人员负荷 | 优先负荷汇总；按 workload.md 传公司已确认的 finalStages 并核对 completionRule，不重复扣减；部门子树用 includeDescendants；需要岗位/零负荷再取人员底册 | 用户需要的风险维度；不为每个人重复取全部工地 |
| 工期与晨报 | 阶段比较按当前 schema 批量 projectIds（现上限100），先分出可比、无计划和落后 | 重点候选再查节点、图文、AI和照片；样本不是全公司排名 |
| 设备 | 少数计数用 total；完整交叉统计一次取台账，用 isOnline、绑定和领用字段分组 | 月度在线表现用 period，逐日趋势才用 day；不按设备逐一查流转 |
| 验收 | 按正确日期维度取得报告，程序按状态和 projectId 分组 | 只对重点报告看审批流程；漏验属于节点数据，未支持批量时不自动扫描全公司 |
| 问题、巡检、签到、整洁度 | 按授权范围和日期批量取所需模块，以稳定ID关联 | 异常和待跟进记录再看详情/图片，不逐工地重复查公司明细 |
| 业主观看 | 汇总 viewCount、去重 ownerId/projectId/日期 | 重点工地的动态与问题，行数不充当观看次数 |

## 时间、重试和交付

- 性能测试记录五个时点：收到问题、技能/工具准备完成、首次有效数据、全部取数完成、最终答案完成。另记计算耗时、成功/失败调用数、页数、返回量及模型/技能版本；无法观测的阶段写未测，不估造。端到端=最终答案完成减收到问题；与接口耗时、取数区间分别报告。
- 遵循用户指定预算；未指定时，大任务默认在5分钟做一次进展检查，给出已完成覆盖和剩余量，不将5分钟承诺为必达SLA。连续失败或无进展时停止无界重试，保留已完成范围和续取位置。独立模块可继续。
- 可重试的临时读错误同参至多重试一次；认证、权限或参数错误先解决原因，不重复轰击。超时只记录发生阶段和可见错误；连接初始化、网络、宿主超时和业务错误分开，不凭 internal_error 判定服务端故障。
- 不默认派出大量子任务取数，不自动建立第二套连接或代理。程序处理完整数据，模型读取汇总与必要异常样本；用户未要求时先交付文字/表格，避免追加HTML、Excel拖延。

## 自报计时的终点

最终答案生成前只能知道“截至当前”的时间，不能预测最终完成时间或用计算结束时间冒充端到端。宿主有“已完成”时长时以该值为准；模型无法读取这个最终值时只给阶段时间、明确最终端到端由宿主计时。报告实际读过的参考文件，不将读过另一版本说成完全未读取。
