# 问题整改与闭环

## 工作台首轮

“最近”未给日期时用近7个自然日（含今天）。首轮分别查该窗口待处理、处理中及已处理待审核的记录（每类首批最多20条，字段按实时schema），按工地归并最多5个重点。必要时只对重点取详情，普通首轮总预算6次业务调用。不查全历史六态或逐类别总数，不把发生日期筛选当作本周处理动作，不从部分记录推断公司无人处理。待审核不等于闭环。只有用户要求总体闭环分析时才展开完整分母和审核维度。

优先用 `list_issue_records` 取得所需范围的六态明细；单工地清单和个案分别用 `list_issues`、`get_issue_detail`。按发生日期选出的是这批问题截至查询时的状态。统计期间整改完成量用实时 schema 支持的 rectifiedStartDate/rectifiedEndDate；整改完成量不自动等于期间审核闭环量。

## 分类规则

| 返回值 | 归类 |
|---|---|
| open、in_progress、rejected | 未闭环；被驳回需重新处理 |
| rectified 且 auditStatusLabel=待审核 | 已提交整改、待复核，仍未闭环 |
| rectified 且 auditStatusLabel=审核通过 | 整改闭环 |
| rectified 且审核键省略 | **当前工具说明明确表示该条记录没有审核流程**，按已整改闭环；不能推断整家公司没启用审核 |
| 审核键为空、未知值或返回与说明矛盾 | 单列待核实，不强行合入闭环；旧连接器没有上述缺键定义时也先单列 |
| invalid、non_worker | 认定关闭；是否纳入闭环率分母按公司规则 |

申诉独立展示，不覆盖整改状态。比率注明所用分母；存在未确定项时先给分类数量，不凑一个精确比例。缺键语义必须来自当前工具定义，不能由个别样本自行推断。

## 分析与输出

- 工地 issueCount 是历史累计总量，不是未闭环。四态列表缺被驳回/非工作人员，不能替代六态统计；工具缺失按 [回退表](tool-fallbacks.md)。
- 整改限时、超时字段依赖公司配置。无期限不称超期；系统节点逾期问题与现场质量/安全问题分开，不重复计算同一线索。
- 按 projectId 关联工地；关键词仅用于定位，不能精确分组。先给工地、问题、状态、可见负责人、期限和建议动作，必要时附原始图片与入口。
- 工地完工不代表问题自动关闭；即使已从在建负荷排除，仍要保留其未闭环事项。

首批明细的来源、类型和负责人分布只适用于已返回记录；即使某状态 total 已知，也不能把这些特点扩大为全量。in_progress=0 只说明当前没有该状态记录，不证明无人认领、没人跟进或流程停滞。
