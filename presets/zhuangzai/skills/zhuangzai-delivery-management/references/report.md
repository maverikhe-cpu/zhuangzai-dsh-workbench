# 工地运营月报

先理解管理目标和交付格式，再选择数据模块。用户给已有报表时先分析文件；只有补数/对照才连接系统。模板仅约束格式时不把其中示例数字当数据；文件与授权公司不一致就分别处理。

## 取数与组织

1. 复用已明确的公司、范围、月份与重点；月份未指定用上一个完整自然月并说明。用户指定模块只查指定模块；未指定时按可用工具做小范围数据探查，再组织有数据的章节。
2. 按 [月报指标](data-and-metrics.md) 选汇总/列表，优先计数与所需分布。完整排名、去重或加权使用完整数据；单工地工具仅展开重点，不为完整月报默认扫描所有工地。
3. 成功空模块可略过；工具缺失/调用失败的模块在结果末尾用一句话说明未完成，不能当无数据删掉。按 [回退表](tool-fallbacks.md) 继续可完成部分。
4. 结构可用“管理摘要 → 模块分析 → 重点工地/人员 → 建议动作”，以用户约定为准。默认 Markdown；需要 HTML/Excel 时再生成，图表取本次统计，不抄模板结论。

## 关键核验

- 当前工地、设备存量是查询时快照，不冒充历史月末。在建采用 [公司口径](company-policy.md)，不直接用 in_progress total 当所有客户业务口径。
- 本月发生问题截至查询时的状态、期间整改完成量、期间审核闭环量分别描述。没有对应时间字段就不混算。
- 巡检、签到、设备在线、业主观看是独立模块，不能相互替代。比率固定分母；环比同比需要同口径上期。
- 完整明细一次计算，不重复逐分类取 total。分组和与总数不符先查未覆盖状态/范围，不能补造数据。
- 交付先讲发现与行动，统计期间/范围和影响判断的缺项简短交代；详细数据表可追问。发送、定时执行另需用户明确指示。

分页、预算和阶段计时见 [性能](performance.md)。
