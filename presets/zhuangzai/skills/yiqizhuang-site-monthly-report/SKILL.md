# 一起装工地运营月报

围绕管理者关心的问题，将授权范围内一起装的真实数据整理成可追问、可核对的月报。使用前读取 [取数与口径](references/data-and-metrics.md)；工具定义、筛选和分页以当前连接实际返回为准。

## 开始

1. 读取用户已给出的公司、月份、部门或工地范围、关注问题和期望交付格式。未指定月份用上一个完整自然月；未指定重点，先做可用模块的概览。公司或授权对象不明确时先核实，不能擅自切换账号或公司。
2. 确认一起装 MCP 在当前工作环境可调用；优先复用已授权连接，不索取或输出 token。获取工具实时定义，按需调用；工具或登录不可用时说清卡点并引导连接，不编造结果。用户提供既有月报模板时先理解其管理目标和字段。
3. 先读少量样本和返回的范围、总数与字段，按需逐页获取所需数据；只对要求的模块取数。对大数据集先说明范围并分批处理，避免无上限地逐工地查询。当前结果、时间段内事件和历史时点存量分开，不能用现在的工地名单冒充上月历史快照。

## 组织月报

以客户需要为准，优先呈现：管理摘要（值得关注的变化和事项）、工地进展与节点、问题跟进、现场形象与 AI 识别、现场签到及线上巡检、摄像头在线情况。没有启用或缺少数据的模块不强行填充；可列出可用数据与可继续追问的方向。每项说明统计时间、范围、单位与计算口径，并提供可核对的工地、人员或记录明细。

先依据明细做统计，再提炼 3–5 个有依据的管理重点，列出涉及工地、原因和建议跟进方向。保持事实和建议分开；若客户要求同比或环比，使用同口径上期数据，不可比就不计算变化。支持明细表、图表或自包含 HTML 报告；选用用户指定格式，未指定则先提供结构清晰的 Markdown。图表数值须能回溯，别使用客户样例中的数字或姓名。

工地在建口径遵循本项目约定：当前工地若已标记完工或处于明确的完工阶段，均不计入当前在建；不要把一般的收尾阶段自动当作完工。各客户阶段名称不确定时先核实。历史某月在建数量只有在有该时点快照或可证明的历史记录时才计算。

## 交付与迭代

给出月报、统计范围、各模块数据来源与关键明细；没有数据与工具调用失败分开呈现。对不完整分页、权限或口径不匹配的指标标注相应范围，不把局部结果当全量。用户可继续追问具体工地和记录；报告内容支持修改为客户习惯的格式。默认仅查询和生成报告；发送到群、创建定时任务或修改业务数据须有用户的具体指示。

## 关键计算与交付前核验

- 项目在建数不能直接采用 `status=in_progress` 的 total：先获取完整候选数据并按本项目口径排除人工完工和明确完工阶段，再去重、核对分页。未完成计算时只报告原始筛选数，不冒充在建数。
- 按发生时间过滤的问题，返回的处理/审核状态是查询时状态，必须写“本月发生的问题截至查询时”；它不能证明本月实际发生多少闭环。需要闭环事件时间和完整范围才能计算期间闭环数，字段缺失则不算。
- 结论、表格和口径说明逐项检查：不得把系统无识别记录说成现场未到、把无可见节点说成未配置、把当前状态说成历史月末或期间事件。不能仅凭没有审核通过状态断言审核未运行或历史从未通过。
