# 人员与工地负荷分析

确认范围、岗位及当前时点。`get_department_tree` 获取可见部门，`list_department_members` 取得指定范围内在职人员，再以 `managerId` 关联 `list_projects` 的工地负责人。岗位 `managerRole` 是返回字段不是接口过滤项，按客户指定岗位在结果中筛选。全量人员和工地均须分页取全、按人员 ID 与工地 ID 去重；有多部门归属时避免重复计数。部门树 memberCount 包含子树且可能是权限裁剪前人数，不用它作可见成员分母。

- 用户的在建管理口径：标记完工或当前阶段明确为完工均不计入；收尾等不明确阶段不能擅自判完工。系统状态与业务口径分别说明。已停工是否纳入负荷取决于客户问题，默认单列正常施工与停工。若无法取全候选或确认阶段，只报告已核对范围，不写全公司完整排名。
- 先呈现每人的有效在建工地数及停工、节点逾期或待处理问题等可核对维度。需要问题数时以工地 ID 可靠关联六态问题明细并按状态拆分；不把工地问题总数当待处理数量。只按查询覆盖的范围做比较，并列或数量相近不强行排名。
- 工地归属部门与负责人所属部门是两个维度：查某部门工地可能包含其他部门负责人，而该部门成员也可能负责其他部门工地。按 ID 显式分出“本部门成员负责本部门工地”“部门外负责人负责本部门工地”“本部门成员负责其他部门工地”，避免把未查其他部门的成员说成没有工地；只说“在已查询的部门工地范围内为零”。核对成员数、外部人数、未匹配人数及工地合计的算术一致性。
- 工地数仅是负荷线索，不代表工时、产值、复杂度或绩效；不同阶段、工地规模和岗位职责可能不同。记录未关联负责人时单列，未取得数据时不记零，不把较高数量直接判为超负荷或考核结论。
- 输出人员、岗位、负责工地数与主要关注点，并建议核实现场负荷、再考虑资源调配。避免给出无法从当前数据支持的人效、离职率或历史时点负荷。
