# 一起装派工管理分析

围绕工程负责人、派工员或客户提出的具体问题，使用一起装已授权的数据，找出需要协调的派工申请和工人安排。分析前读取 [派工数据与口径](references/dispatch-data.md)。工具参数、字段和分页以当前连接实际定义为准。

## 开始

1. 从用户要求确定公司、工地或部门、日期和需要的结果；公司或登录对象不明确时先确认，不擅自切换。用户未指定范围时先根据问题选择合适的范围并说明；重要范围无法合理确定时只问最关键的一项。
2. 使用当前宿主已授权的一起装 MCP，确认工具可用，按需调用派工申请、派工记录及工地工具。不要创建第二套 OAuth、复制令牌或依赖私人脚本和固定路径。若客户端定义缺少最新参数，提示刷新连接或在现有可调用范围内继续，不绕过用户权限。
3. 先查看工具支持的过滤和少量样本；聚合时逐页取得所需范围并核对总数、截断和错误。先缩小到问题相关的时间、工地、状态，避免逐工地全量扫描。需要临时处理大批数据时只在当前任务环境中操作，区分公司与查询范围，不将旧公司缓存混入新公司。

## 从问题组织结果

- **需求和缺口**：以申请为单位列工地、工种、计划开工、需求人数、已派人数、缺口及申请状态；按工种或日期汇总。判断缺口先排除已拒绝或撤销申请，人数为空或为零时单列。紧急程度按计划时间与当前状态说明，不自动认定工地停工。
- **接单和进场安排**：以工人为单位列申请、工地、工种、状态、计划进离场；按需要列待接单、拒单或取消及今天到场。计划时间重叠只作为待核实的潜在撞期；排除取消、拒单，并用稳定工人 ID 匹配。记录工具日期范围是计划进场日，不能直接等同日期区间内所有在场工人。
- **施工面积**：并列显示申请预估面积及该派工记录独立维护的施工/结算面积，单位㎡；没有值显示未填写或未返回，不当作 0。它们与工地房屋/装修面积不同。多工人或多工种面积不直接相加，除非客户明确业务口径且能排除重复。
- **派工响应**：工具有 `includeStatusTimes` 时可针对少量具体申请查询接单/取消时间；结合可靠的对应派工时间才可算响应时长。申请拒绝、撤销、历史到场等无对应数据时不虚构时间线。
- **业务报告**：用户需要日报、周报、月报时，围绕申请 → 派工 → 接单 → 进场 → 日常监督组织；按需求展示分布和可核对明细。分母、时间维度、取消和重复记录的处理与客户先对齐；不能把实时状态当历史当日快照。

输出先回答用户的管理问题，再按需要给清单、汇总与建议；说明查询范围、取数时间和使用的日期口径。没有数据、未填写、字段不可用和查询失败分开处理。可生成 Markdown、Excel 或用户指定的报告；默认只查询与制作文件，不派工、不改记录、不发送消息。

派工结论交付前核对：`actual.days=0` 只表示现场识别记录天数为零；`arrivalToday` 未返回表示不可见。两者都不能推断实际未到场或到场人数为零；待接单、已派工、现场识别各按原字段分别描述。

**待接单与实际到场：** 待接单只表示系统中工人尚未确认接单，不代表人未到现场、不代表不可能出现现场识别记录。解释、表格和建议中都不能说待接单就没进场、没记录是必然结果。实际是否到场须有独立证据或现场核实。
